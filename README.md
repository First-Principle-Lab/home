# First Principle Lab

The homepage for [First Principle Lab](https://fpl.works), an independent home for projects, research, and writing by [Parth Thirwani](https://www.parththirwani.blog/).

Visitors can open production apps, download desktop tools, read selected papers, and find the latest blog posts and social links.

[Visit the site](https://fpl.works) · [Vercel URL](https://first-principle-lab.vercel.app) · [GitHub organization](https://github.com/First-Principle-Lab)

## How it works

This is a static site written in HTML and CSS. There is no JavaScript, framework, package installation, build step, database, or environment configuration required to serve it.

- The layout adapts to desktop and mobile screens.
- The site uses a consistent dark theme.
- Keyboard navigation includes visible focus indicators and a skip-to-content link.
- The logo links to the top of the page without reloading it.
- Smooth scrolling respects the visitor's reduced-motion preference.
- Page metadata includes a canonical URL, social preview image, favicon, robots file, and sitemap.

Project links, selected publications, and the three latest writing entries are maintained directly in the HTML. Blog posts do not update automatically.

## Run locally

Clone the repository and serve the `dist` directory with Python 3:

```sh
git clone https://github.com/First-Principle-Lab/home.git
cd home
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Open [http://localhost:8000](http://localhost:8000). Stop the server with `Ctrl+C`.

Use an HTTP server rather than opening `index.html` directly, because asset URLs start at the site root.

`dist/` contains the source files served to visitors. It is tracked in Git and is not generated by a build command.

## Update the site

| Change | File and location |
| --- | --- |
| Add or edit a project | `dist/index.html`, inside the `.projects` container. Copy an existing `.project` link and update its title, description, destination, and displayed address. |
| Update selected research | `dist/index.html`, inside `.research-list`. Update the year, paper title, and publication link. |
| Update the three blog posts | `dist/index.html`, inside `.blog-list`. Update the article URL, title, visible date, and ISO date in `datetime`. Keep the newest post first. |
| Change social links or the introduction | `dist/index.html`, in the footer or `.intro` section. |
| Adjust colors, spacing, or mobile layout | `dist/style.css`. Theme colors are CSS variables in `:root`. |
| Replace the logo | `dist/fpl-logo.png`. Keep the filename or update all references in the HTML. |
| Change the public domain | Update the canonical and Open Graph URLs in `dist/index.html`, plus `dist/robots.txt` and `dist/sitemap.xml`. Configure the domain in Vercel too. |

Before publishing, check the page at desktop and mobile widths, navigate with the keyboard, and test any changed links. There is no automated test suite or lint command configured.

## Deploy on Vercel

The production project is `first-principle-lab`. The included `vercel.json` serves `dist/` with no build command and sets content-type protection, referrer policy, and a Content Security Policy.

With Node.js and npm installed, authenticate and deploy from the repository root:

```sh
npx vercel login
npx vercel link
npx vercel --prod
```

When linking, select the existing `first-principle-lab` project in the account that owns it. For a separate deployment, create your own project instead. The local `.vercel/` directory is ignored by Git.

To deploy through Vercel's Git integration, import this repository or connect it to the existing project. Use `main` as the production branch, the repository root as the root directory, and `dist` as the output directory. No build or install command is needed.

### Custom domain

The intended production domain is `fpl.works`. Add it in the Vercel project's domain settings and apply the DNS records Vercel provides at the domain's DNS provider.

The existing ChatterStack and Newshog subdomains belong to separate apps. Keep their DNS records when changing the homepage domain. The canonical metadata assumes the homepage is served at `https://fpl.works/`.
